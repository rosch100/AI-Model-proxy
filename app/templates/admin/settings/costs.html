Kosten

Billing-Schlüssel und Abrechnungs-Scope sind getrennte Einstellungen. Beide lassen sich hier pro Provider-Account speichern; der Proxy verwendet die Angaben nur für diesen Tenant.

Azure verwendet weiterhin die Hostidentität des Proxys; es werden keine Azure-Client-Secrets erfasst.

OpenAI: Admin API Key erzeugen

Ein Projekt- oder User-Key aus API keys (Präfix typisch sk-proj- oder sk-) darf /v1/organization/costs und /v1/organization/usage/completions nicht aufrufen. Dafür braucht es einen Admin API Key der API-Platform-Organisation (Präfix sk-admin-). Nur Organization Owner können ihn anlegen. Er ist nicht für Chat Completions nutzbar.

  1. Als Owner anmelden: platform.openai.com/settings/organization/admin-keys
  2. „Create new admin key“, Namen vergeben.
  3. Rechte Restricted: mindestens Usage API → Read (api.usage.read). Zum automatischen Laden der Projektliste zusätzlich Organization Administration → Read. Nicht den Inference-Key wiederverwenden.
  4. Den Wert einmalig kopieren und unten als OpenAI-Billing-Schlüssel speichern.

Die Organization-ID findest du unter Organization → General (org-…), die Project-ID unter Organization → Projects (proj_…). Beide werden unten direkt beim Profil gespeichert; der Refresh filtert Kosten und Tokens auf dieses Projekt.

OpenRouter: Management Key erzeugen

Ein normaler Inference-Key von Settings → API Keys (sk-or-v1-…) liefert 403 auf der Activity-API („Only management keys can perform this operation“). Kosten kommen von GET /api/v1/activity, und die verlangt einen Management API Key. In Organisationen dürfen nur Organization Admins einen anlegen. Er kann keine Completions ausführen.

  1. openrouter.ai/settings/management-keys
  2. „Create New Key“, Name und Ablaufdatum wählen.
  3. Den Wert einmalig kopieren und unten als OpenRouter-Billing-Schlüssel speichern.

Die Workspace-ID ist die UUID des Workspaces unter OpenRouter Settings (Workspaces). Sie lässt sich unten direkt beim Account eintragen. Die Activity-API liefert OpenRouter- und BYOK-Kosten sowie Tokenverbrauch der letzten 30 abgeschlossenen UTC-Tage, gefiltert auf diesen Workspace.

Azure-Hostidentität

Es wird keine Tenant-Credential eingegeben. Der Proxy verwendet seine operatorseitig konfigurierte Managed Identity (einschließlich User-assigned Managed Identity) auf Azure oder Workload Identity bzw. Zertifikatsidentität außerhalb Azure. Die gebundene Resource Group benötigt Cost Management Reader; die gebundene Cognitive-Services-Ressource benötigt Monitoring Reader für separat abgefragte Usage-Metriken.
