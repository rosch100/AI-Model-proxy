Kosten

Richte den Schlüssel für die Abfrage und die dazugehörige Organisation, das Projekt oder den Workspace getrennt ein. Ordne beides dem passenden Konto zu.

Für Azure fragt der Proxy die Daten mit seinem eigenen Zugang ab. Du musst hier keine Azure-Zugangsdaten speichern.

OpenAI: Abrechnungsschlüssel einrichten

Für die Abfrage brauchst du einen Admin API Key der OpenAI-Organisation. Ein normaler Schlüssel von API keys reicht dafür nicht aus. Der Admin-Schlüssel beginnt mit sk-admin-. Er kann nur von einem Organisationsadministrator erstellt und nicht für Chat-Anfragen verwendet werden.

  1. Melde dich als Organisationsadministrator an: OpenAI-Organisationsschlüssel öffnen.
  2. Wähle „Create new admin key“ und gib dem Schlüssel einen Namen.
  3. Wähle Restricted und erteile mindestens Usage API → Read (api.usage.read). Damit der Proxy deine Projektliste automatisch laden kann, erteile zusätzlich Organization Administration → Read.
  4. Kopiere den Schlüssel – er wird nur einmal angezeigt – und speichere ihn unten beim passenden Konto.

Wähle in OpenAI dieselbe Organisation, für die du den Schlüssel erstellt hast. Ihre Kennung (org-…) findest du unter Organization → General. Die Projektkennung (proj_…) findest du unter Organization → Projects → Projekt auswählen → Settings/General. Trage beide Kennungen beim passenden Konto ein; Kosten und Verbrauchswerte werden dann diesem Projekt zugeordnet.

OpenRouter: Abrechnungsschlüssel einrichten

Für die Abfrage brauchst du einen Management API Key von Settings → Management API Keys. Ein normaler Schlüssel für Anfragen reicht nicht aus. In Organisationen kann nur ein Organisationsadministrator diesen Verwaltungsschlüssel erstellen. Er lässt sich nicht für Chat-Anfragen verwenden.

  1. Öffne deine OpenRouter-Verwaltungsschlüssel.
  2. Wähle „Create New Key“ und gib dem Schlüssel einen Namen sowie ein Ablaufdatum.
  3. Kopiere den Schlüssel – er wird nur einmal angezeigt – und speichere ihn unten beim passenden Konto.

Die Workspace-Kennung findest du unter OpenRouter Settings → Workspaces. Falls sie dort nicht angezeigt wird, nutze die offizielle Liste deiner Workspaces. Übernimm den Wert aus dem Feld id, nicht den Namen des Workspaces, und trage ihn beim passenden Konto ein. Angezeigt werden Kosten und Verbrauchswerte der letzten 30 abgeschlossenen Tage.

Azure-Zugriff für die Abfrage

Du musst hier keinen Azure-Schlüssel hinterlegen. Der Proxy verwendet den Zugang seines Servers. Dieser benötigt die Rolle Cost Management Reader für die Ressourcengruppe und zusätzlich Monitoring Reader für das Cognitive-Services-Konto, um Verbrauchsdaten abzurufen.

Die Subscription-Kennung findest du im Azure-Portal unter Subscriptions. Die Kennung der Ressourcengruppe findest du unter Resource Groups → gewünschte Gruppe → Properties → Resource ID. Die Kennung des Cognitive-Services-Kontos findest du unter Alle Ressourcen → Cognitive-Services-Konto → Properties → Resource ID. Um zu prüfen, ob der Proxyserver Zugriff hat, öffne die jeweilige Ressource und wähle Access control (IAM) → Check access. Suche dort nach der Identität des Proxyservers. Microsoft-Anleitung: Zugriffsrollen im Portal prüfen.

Azure-Kennungen und Zugriffsrechte mit der Befehlszeile prüfen

Die folgenden Befehle rufen nur Informationen ab. Melde dich zuerst mit az login an und ersetze die Platzhalter durch deine Werte. az account set ändert nur die aktive Subscription in deiner lokalen Azure-CLI. Rufe niemals account keys list auf und teile keine ausgegebenen Schlüssel.

az login
az account list --query '[].{Name:name, SubscriptionId:id, TenantId:tenantId}' -o table
az account set --subscription '<subscription-guid>'
az account show --query '{subscription:id, tenant:tenantId}' -o yaml

# Die beiden IDs, die in die Azure-Billing-Felder gehören:
az group show --name '<resource-group>' --query id -o tsv
az cognitiveservices account show --name '<cognitive-account>' --resource-group '<resource-group>' --query '{id:id, endpoint:properties.endpoint}' -o yaml

# Deployment-Namen und Modell der Ressource (keine Schlüssel):
az cognitiveservices account deployment list --name '<cognitive-account>' --resource-group '<resource-group>' --query '[].{deployment:name, model:properties.model.name, state:properties.provisioningState}' -o table

Für die Rollenprüfung benötigst du die Object-/Principal-ID der Identität des Proxyservers. Du findest sie unter Azure-Portal → Proxyserver → Identity. Verwende nicht die Client-ID oder die Identität des Cognitive-Services-Kontos. In der Spalte scope muss die Rolle für die angefragte Ressource oder eine übergeordnete Ressource gelten.

RESOURCE_GROUP_ID="$(az group show --name '<resource-group>' --query id -o tsv)"
COGNITIVE_RESOURCE_ID="$(az cognitiveservices account show --name '<cognitive-account>' --resource-group '<resource-group>' --query id -o tsv)"
PROXY_PRINCIPAL_ID='<principal-object-id-der-proxy-hostidentitaet>'

# Erwartet: Cost Management Reader auf der Resource Group (oder geerbt von oben)
az role assignment list --scope "$RESOURCE_GROUP_ID" --all --include-inherited --assignee-object-id "$PROXY_PRINCIPAL_ID" --query "[?roleDefinitionName=='Cost Management Reader'].{role:roleDefinitionName, scope:scope}" -o table

# Erwartet: Monitoring Reader auf der Cognitive-Services-Ressource (oder geerbt)
az role assignment list --scope "$COGNITIVE_RESOURCE_ID" --all --include-inherited --assignee-object-id "$PROXY_PRINCIPAL_ID" --query "[?roleDefinitionName=='Monitoring Reader'].{role:roleDefinitionName, scope:scope}" -o table

Falls die Rollen fehlen, kann ein Azure-Administrator sie mit den folgenden ändernden Befehlen auf genau diesen Scopes zuweisen. Nur mit entsprechender Berechtigung (z. B. User Access Administrator/Owner) ausführen; die Proxy-Hostidentität als Assignee verwenden:

az role assignment create --assignee-object-id "$PROXY_PRINCIPAL_ID" --assignee-principal-type ServicePrincipal --role 'Cost Management Reader' --scope "$RESOURCE_GROUP_ID"
az role assignment create --assignee-object-id "$PROXY_PRINCIPAL_ID" --assignee-principal-type ServicePrincipal --role 'Monitoring Reader' --scope "$COGNITIVE_RESOURCE_ID"

CLI-Referenz: Cognitive Services · CLI-Referenz: RBAC-Rollenzuweisungen · Microsoft: Cost-Management-Scopes.
