# Provider Model Alias Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans (inline). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route native model IDs to catalog-owning tenant profiles and expose unambiguous profile-qualified IDs for explicit account selection.

**Architecture:** A shared alias formatter creates `provider:account/model` IDs, preserving account spaces while escaping reserved account characters. The tenant model endpoint and routing resolver use the same formatter against the authenticated snapshot. Qualified requests pin one profile; native requests route only across profiles listing that model; the existing tenant custom ID retains ordered defaults/failover.

**Tech Stack:** Python 3.13, Flask, SQLAlchemy, Alembic/PostgreSQL, pytest.

## Global Constraints

- Tenant profile catalogs and route priority remain the source of truth.
- Do not add provider/profile configuration or silently substitute a different model.
- Qualified IDs pin the selected profile; native IDs may fail over only among catalog matches.
- Leave non-tenant and Codex model-list behavior unchanged.
- Do not commit; preserve unrelated pre-existing worktree changes.
- Account names may contain spaces; native model IDs may contain `/`.
